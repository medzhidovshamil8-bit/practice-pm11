## Индексы и планы

Созданы индексы price, name, (category\_id, price), UNIQUE(name), (name, category\_id), LOWER(name). Временный индекс supplier\_id создан и удален. EXPLAIN QUERY PLAN для price\>100 и LOWER(name)='хлеб' записан в Результаты.json.

## Измерение

Отдельная таблица benchmark содержит 60 000 строк. На этой машине 40 повторов поиска price=19999 дали медиану без индекса 2.2133 мс, с индексом 0.21525 мс. Числа зависят от кэша и окружения; достоверный вывод здесь — смена плана SCAN на SEARCH USING COVERING INDEX. Сырые планы и методика в Измерение.json.

## Вопросы

Индекс на id INTEGER PRIMARY KEY обычно избыточен: rowid уже обеспечивает поиск. После CREATE INDEX idx ON product(price) план для WHERE price\>100 может показать SEARCH USING INDEX idx или COVERING INDEX idx, но выбор оптимизатора зависит от размера таблицы и статистики.
